# Product Principles

## Vision

Dimcan Platform is a project-first construction workspace for renovation teams. The product should feel calm and simple while still supporting deep, expandable capability as projects become more complex.

## Contractor-First and Client-First Workflow

1. Contractor-first:
   - Capture scope, files, notes, and assembly details in one project workspace.
   - Reduce coordination overhead and repetitive admin tasks.
   - Keep critical decisions and site updates discoverable through activity history.
2. Client-first:
   - Keep communication context clear through structured notes and activity.
   - Surface client-relevant updates without exposing unnecessary technical complexity.

## Calm, Simple, Paper-Like Ease of Use

1. Use warm visual language and straightforward page structure.
2. Keep main interactions obvious and low friction.
3. Prefer clear labels and direct workflows over abstract controls.

## Progressive Reveal

1. Show essential actions first.
2. Reveal advanced actions only when relevant, enabled, or requested.
3. Keep secondary actions in contextual menus instead of persistent button clutter.

## AI Activity Visibility

1. AI-generated or AI-triggered updates should be visible in project activity.
2. Users should be able to distinguish user/system/AI event sources.
3. AI should support decision-making, not obscure it.

## Modular and Extensible Project Stages

1. Project stages should be modular and independently evolvable.
2. Files, notes, assemblies, understanding, and activity should remain composable building blocks.
3. Data structures should support future modules without destructive migration.

## Configurable Tools and Integrations

Design current modules so future integrations can be attached without redesigning core flows.

Future targets include:

1. LiDAR and 3D capture ingestion
2. Supplier integrations
3. Estimating and pricing engines
4. Execution tracking
5. Warranty and post-completion records

## Contractor-Specific Best Practices

1. Capture assumptions and missing information early.
2. Keep change history visible for scope control.
3. Keep scope components (assemblies and component-level edits) traceable.
4. Maintain durable project records that survive device changes.

## Shared Project Data Across Devices

1. Project state must be server-persisted and migration-safe.
2. Device-local fallback can improve resilience, but server state is the source of truth.
3. Workflows should remain usable across desktop, tablet, and mobile contexts.

## AI Should Reduce Admin Work

1. AI features should reduce manual re-entry, status chasing, and repetitive summarization.
2. AI should not introduce additional operational burden to complete normal project tasks.
3. AI interactions should improve clarity, speed, and confidence.
